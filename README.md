# Учебный CRUD на DummyJSON — команда из четырёх человек

Делаем простой каталог товаров: посмотреть список, добавить, изменить и удалить товар.
Обычные HTML, CSS и JavaScript с `fetch`, без React, npm-зависимостей и собственного сервера API.
У товара только три поля: `id`, `title` (название), `price` (цена в долларах).

## Запуск

В корне репозитория:

```bash
python3 -m http.server 8000
```

Открыть <http://localhost:8000/crud.html>. Также можно использовать VS Code Live Server.
Через двойной клик (`file://`) запускать нельзя: браузер блокирует JS-модули.
Для запросов к DummyJSON нужен интернет. Ключ API и регистрация не нужны.

## Как работает фейковый бэкенд

Источники: [репозиторий DummyJSON](https://github.com/Ovi/DummyJSON),
[официальная документация товаров](https://dummyjson.com/docs/products).

| Действие | Запрос |
| --- | --- |
| Read — получить первые 20 товаров | `GET https://dummyjson.com/products?limit=20&select=title,price` |
| Create — добавить | `POST https://dummyjson.com/products/add` |
| Update — изменить существующий | `PUT https://dummyjson.com/products/{id}` |
| Delete — удалить существующий | `DELETE https://dummyjson.com/products/{id}` |

POST и PUT отправляют JSON `{ "title": "Тетрадь", "price": 2.5 }`.
DummyJSON возвращает результат, но **не сохраняет изменения на сервере**.
Поэтому после успешного запроса меняем `app.products` и перерисовываем таблицу.
Повторный GET после изменения делать нельзя: он вернёт исходные данные.
В учебной версии всё хранится в памяти страницы; перезагрузка начинает демонстрацию заново.
Это не общая база данных: изменения одного участника не появляются в браузере другого.

Добавленному товару выдаём свой отрицательный ID: `-1`, `-2`, `-3` через `app.nextLocalId--`.
Не используем ID из ответа POST: сервер не хранит созданные записи, идентификаторы могут повторяться.
Для `id > 0` изменение и удаление идут через API, затем меняется локальный список.
Для `id < 0` изменение и удаление выполняются только в памяти: такого товара на сервере нет.
Не подменять отрицательный ID произвольным существующим ID ради успешного запроса.

Полный CRUD будет готов после объединения всех четырёх частей.

## Общий договор для агентов — прочитать перед работой

1. Работать в своём файле. Не переписывать приложение, не добавлять библиотеки или сборщик.
2. Сохранить экспорт: `initCreate(app)`, `initEdit(app)` или `initDelete(app)`.
   `app.js` уже импортирует и вызывает эти функции один раз до первоначального GET.
3. Не импортировать `app.js` в свой модуль: объект `app` приходит аргументом.
4. Запросы делать через функции из `./api.js`. Они возвращают Promise с JSON,
   а при HTTP-ошибке, проблемах сети или таймауте отклоняют его. Таймаут — 15 секунд.
5. Единственный список — `app.products`. Не заводить отдельную копию списка и не использовать localStorage.
6. Пользовательский текст и названия из API выводить через `textContent`, поля заполнять через `value`.
   `innerHTML` допустим только для постоянной разметки формы без вставки данных.
7. Поля формы: название после `trim()` не пустое, максимум 100 символов;
   цена обязательна, конечное число от 0 до 1 000 000, не больше двух знаков после запятой.
   Для цены использовать `type="number" min="0" max="1000000" step="0.01" required`.
   Нулевая цена допустима; пустую строку нельзя превращать в ноль.
8. Каждую форму поместить в `<fieldset>`, подписать поля через `<label>` и уникальные ID
   с префиксом `create-` или `edit-`. Использовать обычные кнопки и общий CSS.
9. В обработчиках проверять `if (app.busy || !app.ready) return;`.
   При запросе: `app.setBusy(true)`, затем `try/catch/finally`, в `finally` — `app.setBusy(false)`.
   Так все формы и кнопки блокируются на время одного запроса.
10. При ошибке оставить список и введённые поля без изменений, показать `app.showStatus(error.message, true)`.
    Менять список и очищать форму только после успеха. После изменений вызвать `app.render()`.
11. Не менять экспортируемые функции, HTML-контейнеры и структуру товара без согласования с Алтынбеком.

### Что находится в `app`

| Поле / метод | Назначение |
| --- | --- |
| `products` | Массив `{ id: number, title: string, price: number }`; можно изменять или присваивать новый массив |
| `nextLocalId` | Следующий отрицательный ID, стартует с `-1` |
| `busy` | Выполняется операция; менять через `setBusy` |
| `ready` | Первый GET завершился успешно; устанавливает только `app.js` |
| `render()` | Рисует таблицу, кнопки, количество и пустое состояние из `products` |
| `setBusy(boolean)` | Меняет `busy`, блокирует fieldset форм и перерисовывает кнопки |
| `showStatus(text, isError = false)` | Показывает общее сообщение |
| `onEdit(id)` | Назначает Кана; таблица вызывает по кнопке «Изменить» |
| `onDelete(id)` | Назначает Кыл; таблица вызывает по кнопке «Удалить» |

Начальные `onEdit`/`onDelete` равны `null`. Назначить их синхронно внутри `init…`.
Обработчики получают **числовой ID**, не DOM-элемент и не копию товара.
Формы создаются один раз, `render()` их не перестраивает.
`#create-container` принадлежит Нурдаулету, `#edit-container` — Кане.
Кыл использует уже существующие кнопки таблицы и `window.confirm`, отдельный контейнер не нужен.

## Задания, которые можно передать агентам

### Алтынбек — основа и Read (уже сделано)

- Создать отдельную страницу товаров и ссылку из `index.html`.
- Написать общие функции `getProducts()`, `createProduct(data)`, `updateProduct(id, data)`, `deleteProduct(id)`.
- Загрузить первые 20 товаров, проверить ответ, вывести ID, название, цену и действия.
- Показать загрузку, ошибку с повтором и пустой список; безопасно выводить текст.
- Передать один объект `app` модулям остальных участников; подключить заглушки без ошибок импортов.
- После получения остальных частей выполнить общий сценарий приёмки ниже.

Для объяснения: `fetch → проверка response.ok → JSON → app.products → render()`.

### Нурдаулет — Create

Задача агенту: реализуй только `crud/create.js`, соблюдая общий договор этого README.

1. В `initCreate(app)` замени содержимое `#create-container` формой «Название», «Цена», «Добавить».
2. В `submit` вызови `preventDefault()`, проверь поля и доступность операции.
3. Импортируй `createProduct` из `./api.js`; отправь `{ title, price }`.
4. После успешного POST добавь в начало `app.products` объект
   `{ id: app.nextLocalId--, title, price }`, используя проверенные значения формы.
5. Перерисуй список, очисти форму и покажи «Товар добавлен».
6. При ошибке не добавляй товар и не очищай поля. В `finally` разблокируй интерфейс.

Проверить: обычный товар, цена 0, пробельное название, пустая/отрицательная цена,
два добавления с разными ID, двойное нажатие, ошибка сети без ложного добавления.
Объяснение: форма → POST → новый объект в массиве → таблица.

### Кана — Update

Задача агенту: реализуй только `crud/edit.js`, соблюдая общий договор этого README.

1. В `initEdit(app)` создай в `#edit-container` форму с названием, ценой, «Сохранить», «Отмена».
   До выбора товара показывай подсказку; форму скрой.
2. Назначь `app.onEdit(id)`: найди товар в `app.products`, запомни ID, заполни поля, открой форму и поставь фокус.
3. При сохранении заново найди товар по ID: пока форма была открыта, товар могли удалить.
   Если товар исчез, закрой форму с понятным сообщением, не отправляй PUT и не воскрешай запись.
4. Проверь поля. Если ID положительный, вызови `updateProduct(id, { title, price })` из `./api.js`.
   Если отрицательный, обнови товар только локально, без PUT.
5. После успеха измени `title` и `price` найденного товара, сохрани его ID, перерисуй список,
   закрой форму и сообщи об успехе. При ошибке оставь старые данные и открытую форму.
6. «Отмена» закрывает форму без запроса и изменения списка.

Проверить: серверный товар, локально добавленный товар, отмена, валидация,
ошибка API без потери полей, удаление выбранного товара до сохранения, повторный клик.
Объяснение: выбрать ID → заполнить форму → PUT → обновить объект в массиве.

### Кыл — Delete

Задача агенту: реализуй только `crud/delete.js`, соблюдая общий договор этого README.

1. В `initDelete(app)` назначь `app.onDelete = async function (id) { ... }`.
2. Найди товар в `app.products`. Если его уже нет или приложение занято, завершись.
3. Спроси через `window.confirm`, указав название товара. Отмена ничего не меняет.
4. Для положительного ID вызови `deleteProduct(id)` из `./api.js` и проверь `result.isDeleted === true`;
   иначе покажи ошибку и оставь строку. Для отрицательного ID запрос не нужен.
5. Только после успеха удали объект через `app.products = app.products.filter(product => product.id !== id)`.
6. Вызови `app.render()`, покажи «Товар удалён», разблокируй интерфейс в `finally`.

Проверить: подтверждение и отмена, серверный и локальный товар, ошибка API,
двойной клик, удаление последнего товара (должна появиться надпись «Товаров пока нет»).
Объяснение: подтверждение → DELETE → filter массива → таблица.

## Как работать параллельно и объединять код

1. Сначала Алтынбек публикует основу с этим README. Остальные начинают от **одного коммита основы**.
2. В своём клоне каждый получает актуальную общую ветку и создаёт свою:
   `git switch -c feature/nurdaulet-create`, `feature/kana-update` или `feature/kyl-delete`.
   Имя общей ветки проверить через `git branch` — не предполагать, что это `main`.
3. Каждый агент читает README, `crud/app.js`, `crud/api.js` и меняет только свой модуль.
   Заглушки других участников не удалять. Не переименовывать файлы и функции.
4. Если нужен общий CSS/HTML/API, описать изменение Алтынбеку: общие файлы правит он.
   Отдельный тест можно добавить как `tests/create.test.mjs`, `tests/edit.test.mjs` или `tests/delete.test.mjs`.
5. В описании своего коммита/PR указать поведение и выполненные проверки; прислать Алтынбеку ветку или хеш.
6. Алтынбек объединяет готовые ветки по одной: Create → Update → Delete, затем проверяет полный сценарий.
   Работа над ними идёт одновременно, порядок объединения нужен только для удобной проверки.
7. Не делать force-push, не перезаписывать чужие изменения. В одном рабочем каталоге не переключать
   ветки одновременно: использовать отдельные клоны или worktree.

## Приёмка

Автоматическая проверка общего API (Node.js 22.7+; пакеты устанавливать не нужно):

```bash
node --test tests/api.test.mjs
```

Тесты подменяют `fetch`, поэтому проверяют договор запросов и обработку ошибок без интернета.
Дополнительно проверять страницу в браузере с реальным DummyJSON.

- [ ] При открытии виден список первых 20 товаров, во время запроса — загрузка.
- [ ] При недоступном API видна ошибка; «Повторить загрузку» работает после восстановления сети.
- [ ] Создать два товара: обе строки появляются, ID различаются.
- [ ] Изменить один исходный и один новый товар: обновляются только выбранные строки.
- [ ] Отменить редактирование: данные не меняются.
- [ ] Отменить удаление, затем подтвердить: строка исчезает только после подтверждения и успеха.
- [ ] Ошибочный POST/PUT/DELETE не меняет массив; повторное нажатие не дублирует запрос.
- [ ] Удалить все строки: отображается пустое состояние, форму добавления можно использовать.
- [ ] Перезагрузить: исходные данные возвращаются — это ожидаемое поведение фейкового API.
- [ ] В DevTools → Network видны GET/POST/PUT/DELETE для серверных товаров.
- [ ] Для новых отрицательных ID PUT/DELETE не отправляются; причину команда умеет объяснить.
- [ ] Клавиатурой доступны формы и кнопки; на телефоне таблица прокручивается без обрезания страницы.
